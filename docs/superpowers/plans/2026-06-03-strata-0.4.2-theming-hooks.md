# Strata 0.4.2 — Softer border & scrollbar theming defaults Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose four granular border/shadow theme tokens with softer light-theme defaults, and auto-collapse the horizontal scrollbar row when columns fit the viewport — resolving issue #10.

**Architecture:** Pure CSS-custom-property additions in `src/theme/tokens.css`, rewired selectors in `src/strata.css`, theme-file overrides so high-contrast/dark stay bold, plus one className toggle in `GridRoot.tsx` driven by the existing `maxScrollLeft` metric. The collapse decision is extracted into a pure, unit-tested helper; the visible scrollbar chrome collapses by height (not `display:none`) so the hidden measurement scroller keeps its width and overflow re-detection keeps working.

**Tech Stack:** React 18 + TypeScript, Vitest + @testing-library/react (jsdom), tsup build. CSS via plain custom properties.

**Spec:** `docs/superpowers/specs/2026-06-02-strata-0.4.2-theming-hooks-design.md`

**Key facts for the engineer (read first):**
- Token *defaults* live ONLY in `src/theme/tokens.css` (the `.strata-grid` block there). The `.strata-grid` block in `src/strata.css` (line 8) only declares layout vars, not the color tokens — do NOT duplicate token defaults into it.
- Never hand-edit anything under `dist/`. The build copies `src/strata.css` and `src/theme/*.css` into `dist/` (`npm run build`).
- jsdom has no layout engine: `scrollWidth`/`clientWidth` are `0`, so `maxScrollLeft` is `0` in tests and the scrollbar row is "collapsed" by default. Tests rely on this rather than simulating overflow.
- Run all tests with `npx vitest run` (single run, no watch). Run one file with `npx vitest run <path>`.

/**

  return maxScrollLeft <= 0;
}

## Border & frozen-pane tokens

Fine-grained control over separators and the frozen/pinned pane treatment:

| Token | Controls | Default |
| --- | --- | --- |
| `--strata-border-cell-vertical` | Data-cell vertical separator | `#eef0f3` |
| `--strata-border-header-vertical` | Header-cell vertical separator | `#e5e5e7` |
| `--strata-border-frozen` | Selection / pinned pane separator | `#d8dce2` |
| `--strata-shadow-frozen` | Pinned-pane shadow | `1px 0 0 rgba(148, 163, 184, 0.16)` |

The horizontal scrollbar row auto-collapses when columns fit the viewport (no
overflow), so a grid sized to its content shows no empty scrollbar strip.
```

## [0.4.2] — 2026-06-03

### Changed

- **Softer default border treatment** — data-cell vertical separators and the
  frozen/pinned pane now use lighter defaults, and the heavy frozen-pane "wall"
  (a hard `2px 0 0` shadow) is replaced by a subtle shadow. This is a visible
  change to the default light theme. Restore the previous look by setting
  `--strata-border-cell-vertical: #e5e5e7`, `--strata-border-frozen: #d1d1d6`,
  and `--strata-shadow-frozen: 2px 0 0 #d1d1d6`.

### Added

- **Granular border tokens** — `--strata-border-cell-vertical`,
  `--strata-border-header-vertical`, `--strata-border-frozen`, and
  `--strata-shadow-frozen` let consumers tune vertical separators and the
  frozen-pane treatment independently of horizontal rules and the grid outline.
- **Auto-collapsing horizontal scrollbar row** — the scrollbar row collapses its
  height when columns fit the viewport, removing the empty scrollbar strip.

```
