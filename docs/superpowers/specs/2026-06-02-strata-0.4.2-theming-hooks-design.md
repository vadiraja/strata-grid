# Strata 0.4.2 — Softer border & scrollbar theming defaults (design)

- **Issue:** [#10 — Expose softer list-grid border and scrollbar theming defaults](https://github.com/vadiraja/strata-grid/issues/10)
- **Target release:** 0.4.2 (patch)
- **Status:** Design approved 2026-06-02

## Problem

Integrating `strata-grid@0.4.1` into consumer list pages, the default grid border
treatment reads more like an HTML table than a polished data grid:

1. Regular data-cell vertical separators are too strong (and vertical/horizontal
   rules cannot be tuned independently — both come from `--strata-border-cell`).
2. The frozen / pinned / selection pane separator is too prominent — a hard
   `box-shadow: 2px 0 0 var(--strata-border)` on top of a 2px border reads as a
   heavy "wall".
3. The horizontal scrollbar row stays visible (its `border-top` + reserved
   height) even when columns fit the viewport and there is no overflow.

Consumers currently patch all of this with scoped integration CSS. These are
useful library-level hooks and defaults.

## Decisions (locked)

- **Soften the shipped light-theme defaults** (not hooks-only). The default
  appearance changes for all consumers; ship in 0.4.2 with a clear changelog
  note. The softening is subtle.
- **Auto-collapse the horizontal scrollbar row** when there is no overflow
  (no consumer config / prop).
- **Width-fitting is out of scope** — consumers measure and fit columns
  themselves; this work only makes the scrollbar row collapse cleanly when they do.
- **Stay in Strata's neutral-gray palette** for the new defaults rather than
  importing the consumer's blue-tinted hexes. Exact hex values are easy to tweak.

## Design

### 1. New theme tokens

Declared in both `src/theme/tokens.css` and the `.strata-grid` block in
`src/strata.css` (the two must stay in sync — tokens.css is the published theme
entry, strata.css carries inline defaults).

| Token | Controls | New light default | Replaces |
|---|---|---|---|
| `--strata-border-cell-vertical` | data-cell **right** separator | `#eef0f3` | `--strata-border-cell` (`#e5e5e7`) |
| `--strata-border-header-vertical` | header-cell **right** separator | `#e5e5e7` | `--strata-border-cell` (`#e5e5e7`, unchanged) |
| `--strata-border-frozen` | selection / left / right pinned-pane separator | `#d8dce2` | `--strata-border` (`#d1d1d6`) |
| `--strata-shadow-frozen` | pinned-pane shadow | `1px 0 0 rgba(148, 163, 184, 0.16)` | hard `2px 0 0 var(--strata-border)` |

Unchanged:
- Data-cell **bottom** (horizontal) separator keeps `--strata-border-cell`.
- Header **bottom** underline keeps `--strata-border`.
- Outer grid border keeps `--strata-border`.

Right pinned pane uses the mirrored shadow direction (`-1px 0 0 …`); the
`--strata-shadow-frozen` token holds the left-pane form and the right pane negates
the X offset in its own rule.

### 2. CSS wiring (`src/strata.css`)

| Selector | Property | From | To |
|---|---|---|---|
| `.strata-cell` | `border-right` color | `--strata-border-cell` | `--strata-border-cell-vertical` |
| `.strata-header-cell` | `border-right` color | `--strata-border-cell` | `--strata-border-header-vertical` |
| `.strata-selection-pane` | `border-right` color | `--strata-border` | `--strata-border-frozen` |
| `.strata-pane-left` | `border-right` color | `--strata-border` | `--strata-border-frozen` |
| `.strata-pane-left` | `box-shadow` | `2px 0 0 var(--strata-border)` | `var(--strata-shadow-frozen)` |
| `.strata-pane-right` | `border-left` color | `--strata-border` | `--strata-border-frozen` |
| `.strata-pane-right` | `box-shadow` | `-2px 0 0 var(--strata-border)` | right-mirrored `--strata-shadow-frozen` |

### 3. Auto-collapse the horizontal scrollbar row

**Constraint.** `updateScrollbarMetrics` in `GridRoot.tsx` measures overflow off
the hidden native scroller (`.strata-horizontal-native-scrollbar`) *inside* the
scrollbar row, and a `ResizeObserver` watches that scroller. Using
`display: none` on the row would zero its `clientWidth`/`scrollWidth`, so
`maxScrollLeft` would stick at 0 and overflow that appears later (resize, data
change, column add) would never be re-detected.

**Approach.** Toggle a modifier class on the row when `maxScrollLeft <= 0`:

```
<div className={`strata-horizontal-scrollbar-row${maxScrollLeft > 0 ? '' : ' strata-horizontal-scrollbar-row--collapsed'}`} ...>
```

CSS collapses only the *visible chrome* while preserving the scroller's width:

```css
.strata-horizontal-scrollbar-row--collapsed {
  height: 0;
  border-top: none;
  overflow: hidden;
}
```

Because the collapse changes the row's **height** (not width), the inner
scroller keeps its horizontal `clientWidth`, so measurement and the
`ResizeObserver` keep working and the row reappears the instant center columns
overflow again. The existing track/thumb `opacity` toggles are retained as a
belt-and-suspenders measure.

### 4. Themes that must stay bold

The new granular tokens are declared in the base theme, so theme files that want
strong borders must override them explicitly:

- `src/theme/high-contrast-light.css` — set the four tokens to the strong
  `#000000` border / hard shadow equivalents.
- `src/theme/high-contrast-dark.css` — set them to the `#ffffff` equivalents.
- `src/theme/dark.css` — set `--strata-border-cell-vertical` /
  `--strata-border-header-vertical` to `#38383a` (current `--strata-border-cell`),
  `--strata-border-frozen` to `#48484a` (current `--strata-border`), and
  `--strata-shadow-frozen` to a dark-appropriate subtle shadow.

Mirror any base-token additions into `dist/` only via the build step (do not
hand-edit `dist/`).

- `CHANGELOG.md`: 0.4.2 entry calling out the **visible default change** plus the

## Testing

- **Unit/DOM** (`src/components/DataGrid.columns.test.tsx` or a focused test):
  assert `.strata-horizontal-scrollbar-row` gains `--collapsed` when center
  content fits and loses it when content overflows.
- **Visual / manual** via the playground: confirm softened data-cell verticals,
  softened frozen pane (no heavy wall), and that high-contrast + dark themes are
  unchanged.

## Out of scope

- Consumer-side column width-fitting (measure viewport, reserve chrome, compress
  fixed columns). Consumers own this; the scrollbar-row collapse simply makes the
  result clean.
- Any new component props or JS API — this release is tokens + one internal
  class toggle only.
