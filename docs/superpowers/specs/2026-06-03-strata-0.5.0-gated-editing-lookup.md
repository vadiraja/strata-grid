# Strata 0.5.0 — Gated editing, modal editor surface & enterprise lookup (design)

- **Target release:** 0.5.0 (minor — new opt-in capabilities, no breaking default change)
- **Status:** Design approved 2026-06-03
- **Builds on:** existing editing stack (`EditableConfig`, `editors/`, `use-edit-state`,
  `cell-range`, `FillHandle`, `use-history-manager`)

## Problem & intent

The grid already supports inline cell/row editing, range selection, a fill handle,
dirty tracking, and (structural) undo/redo. Three enterprise gaps remain:

1. **No accident guard.** Editing is live whenever an `editable` config is present.
   Enterprise users want an explicit *edit mode* the user must enter before any
   change is possible.
2. **Inline-only surface.** Some columns (long text, multi-field, lookup) are better
   edited in a **modal dialog** than in-place.
3. **No object/reference editing.** Enterprise cells often hold a *reference to an
   object* chosen by **searching** a data source. Selecting a result should populate
   the cell and optionally **cascade-fill** related columns (e.g. pick a Part →
   fill Description, UOM, Cost).

## Decisions (locked)

| # | Decision | Choice |
|---|---|---|
| 1 | Edit-mode scope | **Whole-grid toggle** ("edit this sheet" model) |
| 2 | Inline vs modal | **Per-column** `editSurface` config |
| 3 | Lookup result mapping | **Declarative field map + optional `onSelect` callback** |
| 4 | Data write-back | **Both** — keep controlled callbacks AND add opt-in auto-apply |
| a | Gate default | **Non-breaking**: `editing` defaults on when uncontrolled; gate is opt-in via `editing={false}` |
| b | Lookup cell value | Stores an **`{ id, label }` reference** by default (overridable) |
| c | Tabular TSV copy/paste | **Out of scope** — tracked as a 0.5.x follow-up |

## Design

### 1. Edit-mode gate (whole-grid)

New `DataGrid` props:

```ts
editing?: boolean;                  // controlled edit mode
onEditingChange?: (next: boolean) => void;
showEditToggle?: boolean;           // optional built-in toolbar toggle
```

Behavior:
- **`editing === false`** → grid is fully read-only: edit triggers, fill handle,
  paste, and edit keyboard shortcuts are inert; editable indicators hidden.
  Selection / range-selection / sorting / filtering still work.
- **`editing === true`** → existing `editable` column rules apply as today.
- **Uncontrolled default = `true`** so existing consumers (who pass `editable`
  without `editing`) are unaffected. Opting into the gate means rendering with
  `editing={false}` initially and flipping it (own button or `showEditToggle`).

Implementation notes:
- Thread an `editingEnabled` boolean from `DataGrid` → `GridRoot` → keyboard /
  edit-state / fill-handle / context-menu wiring; each gates its activation on it.
- The built-in toggle (when `showEditToggle`) lives in the toolbar/header area and
  calls `onEditingChange`.

### 2. Per-column edit surface

New column field:

```ts
editSurface?: 'inline' | 'modal';   // default 'inline'
```

- `'inline'` → current in-place editor behavior.
- `'modal'` → activating the edit opens a dialog hosting the **same** editor
  component for that column, plus existing validation (`validators.ts`), with
  explicit **Commit / Cancel**. Escape / backdrop = cancel; the cell does not
  commit until the dialog commits.
- A shared `EditModalHost` component renders the active modal editor; only one
  modal edit is active at a time (auto-commit/cancel rules mirror inline edits).

### 3. Lookup editor

New built-in editor type:

```ts
export type EditorType = 'text' | 'number' | 'select' | 'date' | 'checkbox' | 'lookup';
```

Column `lookup` config:

```ts
interface LookupConfig<TRow, TResult = Record<string, unknown>> {
  /** Consumer-provided async search. Debounced; called after minChars. */
  search: (query: string, ctx: { row: TRow; columnId: string }) => Promise<TResult[]>;
  /** How each result row renders in the list. Default: String(result). */
  renderOption?: (result: TResult) => ReactNode;
  /** What value lands in THIS cell. Default: { id, label } reference
   *  built from idField/labelField. */
  getValue?: (result: TResult) => unknown;
  /** Field on TResult used as the reference id. Default: 'id'. */
  idField?: string;
  /** Field on TResult used as the display label. Default: 'label' / 'name'. */
  labelField?: string;
  /** Declarative cascade-fill: result field -> target column id. */
  map?: Record<string, string>;
  /** Escape hatch for computed/derived fills. Runs after map. */
  onSelect?: (result: TResult, rowApi: LookupRowApi) => void;
  minChars?: number;     // default 1
  debounceMs?: number;   // default 250
}

interface LookupRowApi {
  setCell: (columnId: string, value: unknown) => void;
}
```

Surfaces:
- **Inline** (`editSurface: 'inline'`) → combobox/popover anchored to the cell with
  async results, keyboard navigation, loading + empty states.
- **Modal** (`editSurface: 'modal'`) → the same search UI in a dialog, better for
  browsing larger result sets.

Selection flow:
1. User picks a result.
2. The cell value = `getValue(result)` (default `{ id, label }`, where `label` is
   derived from `renderOption` / a `labelField`, `id` from an `idField` — both
   configurable; sensible defaults documented).
3. If `map` is present, each `resultField → columnId` writes the raw mapped value
   into the sibling cell.
4. If `onSelect` is present, it runs last for custom/derived writes.
5. The cell write + all cascade writes are committed as **one transaction**
   (single change event, single undo step — see §5).

### 4. Data write-back (controlled + opt-in auto-apply)

- **Controlled (unchanged default):** existing callbacks (`onCellEditEnd`,
  `onRowEditEnd`, `onFillRange`) still fire; consumer updates their store. A lookup
  cascade emits a single multi-cell change event the consumer applies.
- **Auto-apply (opt-in):** a new mode where the grid owns mutation of a supplied
  data array via an updater:

  ```ts
  autoApply?: boolean;
  onDataChange?: (next: TRow[]) => void;   // grid emits the new array
  ```

  When enabled, typed edits, fills, and lookup cascades are applied to the data
  automatically (cascade as one transaction). Suited to client-owned data; for
  server-driven data sources, leave `autoApply` off and use callbacks.

### 5. Undo / redo

- Extend `use-history-manager` to record **cell-value edits** (today it covers
  structural tree edits).
- A lookup selection (cell value + cascade fills) is pushed as **one atomic
  history entry** so a single undo reverts the whole cascade.
- History applies in both controlled and auto-apply modes (in controlled mode it
  re-emits change events for the consumer to apply).

## Public API additions (summary)

- `DataGrid` props: `editing`, `onEditingChange`, `showEditToggle`, `autoApply`,
  `onDataChange`.
- Column config: `editSurface`, `lookup` (+ `editorType: 'lookup'`).
- Types: `LookupConfig`, `LookupRowApi`, `LookupSelectEvent`, multi-cell change event.

## Testing

- **Gate:** read-only when `editing={false}` (no editor opens, fill handle/paste
  inert, indicators hidden); editable when `true`; uncontrolled default stays on.
- **Modal surface:** modal opens for `editSurface: 'modal'`, commit writes, cancel
  discards, validation blocks invalid commit.
- **Lookup:** async search debounce + minChars; selection writes cell via `getValue`;
  `map` cascade-fills sibling columns; `onSelect` runs after map; one undo reverts
  the whole cascade.
- **Write-back:** controlled mode emits multi-cell change event; auto-apply mutates
  the array and emits `onDataChange`.
- Regression: existing inline/row editing, fill handle, range selection unaffected.

## Out of scope

- **Tabular TSV copy/paste** (Excel clipboard interop) — separable follow-up
  (0.5.x). Current clipboard remains subtree-based.
- Consumer-side column width-fitting.
- Server-side search transport (the consumer's `search` callback owns it).

## Rollout

- Minor release **0.5.0**; CHANGELOG documents new opt-in props and the lookup
  editor. No default behavior change for existing consumers.
- Docs: theming/editing guide gains an "edit mode", "modal editing", and "lookup
  editor" section with examples.
